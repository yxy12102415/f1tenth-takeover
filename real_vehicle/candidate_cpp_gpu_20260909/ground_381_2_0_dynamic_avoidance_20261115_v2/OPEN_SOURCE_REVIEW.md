# 开源实车参考与本次修改

当前状态：独立开发版，尚未完成实车验收；不启动电机，不覆盖成功基线。

## 参考来源

1. [ForzaETH Race Stack](https://github.com/ForzaETH/race_stack/tree/ros-noetic)：主参考。论文实车结果使用 ROS1，故克隆 ros-noetic，不能把当前 ROS2 分支直接视为相同验证程度。重点阅读 perception/abd_tracker/README.md、opponent_tracker/src/tracking.py、detect.py 和 planner/spliner。
2. [Predictive Spliner](https://github.com/ForzaETH/predictive-spliner)：重点阅读 src/sqp_avoidance_node.py 和 collision_prediction.py。将障碍预计占用与自车到达时间结合；Frenet 横向优化同时约束道路边界、障碍、曲率与起始连续性。
3. [Multiopponent Predictive Spliner](https://github.com/ForzaETH/multiopponent-pspliner)：参考多障碍接口，而非强制锁定唯一前车。
4. [TUM GraphBasedLocalTrajectoryPlanner](https://github.com/TUMFTM/GraphBasedLocalTrajectoryPlanner)：补充参考多层图候选路线和速度规划；是赛车规划项目，不将其误称为本车或 F1TENTH 的直接实车验证。

精确版本与本地路径见 OPEN_SOURCE_REFERENCES.json。本次没有复制上游算法源文件；Race Stack 根目录 MIT 许可随克隆保留，其他仓库未发现独立许可时不能默认允许复制发布。没有将它们加入本车运行依赖。

## 问题与处理

| 当前问题 | 上游可借鉴的方法 | 当前独立 C++ 实现与限制 |
|---|---|---|
| 轮胎点簇 ID 变化导致停车 | 检测、关联、静动态分类分层 | 几何与预测位置关联，不把 cluster ID 当身份；相近支持点可合并，所有实际回波仍进入碰撞检查 |
| 历史障碍不断变大 | 可见性控制的生命周期，动态状态预测 | 原始支持历史限 0.6 s；普通保持最多 1 s；遮挡转明确未知占用，可见区域连续 3 扫空闲才清除，不按时间盲删 |
| 地图墙边被估计为运动目标 | 地图边界筛选，基于多帧运动证据分类 | 保留独立静态地图和实时回波；长基线运动与形状一致性验证，接近墙不能永久禁止运动 |
| 绕行大、出弯摆动 | 有道路边界和曲率约束的 Frenet 优化 | 延用现有自由走廊 QP、左右候选、换道连续性代价和完整车身验证；最大横移 0.65 m 是搜索上界，不是固定绕行距离 |
| 搜索慢导致观测过期 | 模块化检测/规划/控制 | 观测 20 Hz 独立于搜索线程；控制命令前复核最新观测和预测轨迹；原始 scan/pose 仍 0.5 s 超时，路径提案单独最长 1 s，不能刷新旧测量时间冒充新数据 |
| 终点前急转/停车 | 连续曲率和终端约束 | 短路径也检查三点曲率；取消将回正强行压到末段 5 cm；终点候选必须回到原坐标，最终朝向仅记录 |

这是借鉴设计的原生实现，不是完整移植 ForzaETH，也没有实现其 EKF/GP 预测。当前运动估计仍为有限窗口常速度估计。仅凭几组静止扫描不训练 GP；需要实际连续运动轨迹，再判断是否值得增加学习预测。

## 本车约定

沿用 381 2.0 原曲线路线、原起点和终点；RViz 参考路径直接读取 runtime_assets.json，避免显示旧直线。PID 横向控制和动态 MPC 结构保留，MPC 参考 Fitzpatrick 权重。速度指令最高 2.0 m/s，正常行驶最低 0.5 m/s，加速度上限 1.0 m/s²；起步和最终停车过渡不宣称瞬时跨越低速。MPC 加速度上限直接写入优化器输入约束，不能仅在求解后裁剪。

0.5 m/s 指令并不保证实际轮速不顿挫：既有日志已出现低速指令正常、轮速近零，需要另行核对 VESC 速度反馈、驱动死区和纵向跟踪。不能用放宽规划约束掩盖它。

## 验证与启动

最新验证结果见 reports/dynamic_preparation/ 和 DYNAMIC_PREPARATION_STATUS.json；复制来的历史 reports 不代表本版验证结果。先完成原生测试、ROS 无驱动闭环与故障测试，再安排静止前车、低速移动前车。当前 physical_commissioning_enabled=false，旧成功入口保留。本次不自动启动实车。

## 闭环验证进一步发现的接口错误

- 静止物体显露侧面时，点云外框单边变长不代表平移。速度估计改为检查两条支持边的同向位移，避免把形状显露当成速度。
- 静态地图快速检查用三段覆盖圆，每个圆包住三分之一车身；保留地图离散、定位与时间步覆盖余量。原整车对角线大圆会高估横向宽度。
- 移动障碍按预计相遇时刻验证，不能同时把其当前位置锁成整条未来路径的永久禁区。其测量点只从静态未来扫掠中分离，完整动态占用仍在输出前独立验证；尚未确认运动的物体继续按静态处理。
- 速度参考与硬约束分开：MPC 曲率/地图参考保留提前减速和响应余量，优化器硬上限对应当前实际安全上限及 2 m/s 硬件范围；PID 继续使用既有响应余量。不能把每次降低的参考立即变成所有预测步的硬速度上限。
- 搜索时间用尽单独报告 generic_search_budget_exhausted，不冒充已证明几何无解。

## 跟随与完整超车的区分

新增通用跟随退路：对前方同向移动占用，不锁定目标身份；若剩余路程不足以完成超过、回归及保守停车，则规划回参考线并将速度参考降至目标纵向速度（最低 0.5 m/s），而非继续扩大横移。实际预测轨迹仍必须通过完整占用校验。低于可持续最低速度、没有足够间距或没有可行通道时，仍允许停车。

381 2.0 闭环中的移动目标测试只证明动态障碍处理和跟随；不把跑到终点当成完整超车成功。另创建独立 15 m 直线软件场景验证完整超过与回归。该场景不修改实际地图、路线或起点。

## 验收范围与尚未完成的部分

381 的必要软件验收为两个控制器各自的无障碍、静态绕障、移动跟随及断流停车，共 8 项。另有独立宽阔 15 m 直线的完整动态超车实验，横移搜索上限为 0.90 m；实际 381 配置仍为 0.65 m。两组结果单独报告，绝不把 381 跟随完成替代完整超车验收。

长直线目前仍可能因为候选路线曲率、搜索预算或预测占用冲突而失败。后续完整版应将曲率作为优化约束，而不是只靠平滑代价后验筛除，并进一步统一规划到达时间与控制器的速度轨迹。ForzaETH 的 SQP 中包含转弯半径约束，这一点目前尚未完整移植。临时开发的 QP 原型位于 /tmp，没有合入运行版本。

本次保留已通过的静态搜索与 1.2 s 静态过程模型，仅将运动占用规划前视扩至 1.6 s，为 1.2 s MPC 预测保留正常规划/传输余量；输出仍由最新占用独立复核。移动情况下为 QP 预留候选搜索预算。候选细化的到达时间起点改为候选自己的起点，并优先尝试车辆已处于的绕行侧，避免错误坐标和无意义换边。
